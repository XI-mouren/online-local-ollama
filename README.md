# ollama-plugin

给本地小模型装上联网能力的 NoneBot2 插件。

> 本地部署的小模型有两个硬伤：知识有截止日期，且大多不支持原生 Function Calling。
> 这个插件用 Prompt + 多轮交互手工实现了工具调用链路，让 3B 级别的本地模型也能回答训练数据之外的问题。

## 工作流程

一条用户消息会触发 **4 次模型交互**：

```
用户消息
  │
  ├─ ① 意图分类 ─── 这条消息需要联网查才能答好吗？  → no ──→ 直接用离线模型回复
  │                  (temperature 0.0001, num_predict=10)
  │
  ├─ ② 查询改写 ─── 把口语化消息改写成检索用 query
  │
  ├─ ③ 检索 + 摘要 ── ddgs 搜索 → 截断 → 交给模型压缩成一段关键信息
  │
  └─ ④ 检索增强生成 ── 模型结合摘要与历史上下文生成最终回复
```

## 关键设计

| 设计 | 解决的问题 |
|---|---|
| 意图前置判断 | 不是所有消息都要检索，避免无谓的搜索开销与延迟 |
| 低温度 + 输出长度限制 | 意图分类只需 yes/no，用 temperature 0.0001 与 num_predict=10 压成本 |
| 多层截断 | 检索 query 截 200 字符、每条摘要截 1000 字符，保护有限的上下文窗口 |
| 滑动窗口 | 会话历史最多保留 20 轮，超出自动丢弃最早一轮 |
| 失败降级 | 意图分类任何异常一律返回 `no`，退化为普通对话；摘要失败则回退原始检索结果 |
| 会话隔离 | 群聊共享一份上下文，私聊按用户独立；支持 `/clear`、`/change` 换模型 |

## 安装

```bash
pip install -r requirements.txt   # aiohttp ollama ddgs
```

在 NoneBot 配置中填写模型列表：

```dotenv
Model_list=["CHAT_OFFLINE","q4_chaoji"]
```

## 命令

| 命令 | 说明 |
|---|---|
| `@机器人 <消息>` | 自动判断是否需要联网，然后回复 |
| `/clear` `/清空` | 清除当前会话历史；`/clear all` 清除全部 |
| `/change` `/换模型` | 切换离线回复使用的模型 |

## 已知限制

- 检索与摘要为同步调用，在异步 handler 中会阻塞事件循环，高并发下会拖慢整个机器人
- 会话历史存在内存字典中，进程重启即丢失，且未做并发加锁
- 当前仅支持单次检索，未实现「检索结果不满意→改写 query 重试」的多轮迭代
